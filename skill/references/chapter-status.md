# 章级状态与验证范围

1.5.0 增加可选 `disciplineChecks` 派生状态，见[明确配置的学科检查](discipline-checks.md)。它独立于原有五项状态：实际规则命中的算术/维度失败或缺测阻断关联章节；配置无效阻断全局可学习结论。未配置不标为学科通过，配置通过也不替代人工审校。

章级状态由构建器派生在 `validation.chapterStatus`，不从一句“全书通过”推断各章完成。首页先显示本次可学习范围和可用章数，章卡片保留学习范围、审校和抽检的短状态；章节开头的详情默认折叠；来源页显示各章对照表与证据。

- **内容整理**：按独立原资料清单检查本章来源条目的覆盖位置。未映射条目仍计入；无法归章的条目另列。数量齐全不证明讲解正确。
- **审校**：汇总本章实际目标的语义审校时效。正文、题目或相关资料变更后，不继续显示旧审校有效。旧 v1 自由文本记录为待核对。
- **独立抽检**：显示本章入样、已审数量与结论。样本通过只代表所列样本，未入样不写通过。见 [独立抽检](independent-review.md)。
- **离线功能、视觉检查**：分别汇总实际记录的目标范围。构建成功不自动产生浏览器或视觉通过；只测一章或一个题目不能扩大到其他内容。

## 可学习范围与分批交付

每章另有派生的 `availability`：`ready`（可学习）、`partial`（部分待补）、`pending`（待补）。可学习要求本章纳入学习的原资料条目已完整映射、声明的小问没有遗漏、正文与答案有内容、当前审校记录有效且没有必要待补材料；本次要求的独立抽检也须完成。已有抽检失败、失效或无效记录同样不能显示可学习。旧 v1 自由文本审查不会自动满足此条件。

`ready` 是学习内容与所记录审校的范围判断，不是新的正确性认证，也不代替离线功能或视觉验收。章节的五维状态继续独立保留。仅按本任务明确用途作存档或对照的资料，仍展示其缺口，但不会无理由阻断已整理并审校的学习主线；没有明确用途时不猜测。

空的待补章节须明确保存：

```json
{"id":"ch3","title":"第三章（待补）","sections":[],"pending":{"reason":"本次未提供第三章正文，等待补充原资料。"}}
```

该占位只能在 `scope.completeness` 为 `excerpt` 或 `incomplete` 时使用。已有部分内容的章节也可使用 `pending.reason` 说明剩余缺口；原因未移除前不算可学习。没有待补说明的空章仍是结构错误。占位保留真实章节 ID 与顺序，后续补资料沿用 ID，不通过删章让完成度变高。

`taskContract.pendingMaterials` 中每项默认是必要资料。只有本次用户约定明确允许晚些补充、且不影响当前学习内容时，才使用 `required:false` 并记录 `optionalReason`：

```json
{"chapterId":"ch2","description":"后续补充的历史照片","required":false,"optionalReason":"用户仅要求将照片留作背景对照；现有正文和练习不依赖它。"}
```

可选资料始终展示，不计入必要缺口。`required` 必须是布尔值；缺省为 `true`，字符串 `"false"` 不会被当作可选。必要资料尚待补或章节有 `pending` 时，不能把全书范围标为 `complete`。

顶层 `validation.chapterStatus.learningRange` 包含可用章数、部分/待补章数、待处理事项数、`prefixChapterIds` 和 `readyRanges`。前者是**从本次收录首章开始**的最长连续可用序列，后者保留其他连续可用段。例如七章中第3–5章待补时，首段为第1–2章，第6–7章另列；第一章待补时首段为空，不跳过它宣称前几章完整。节选从原书第八章开始，也只按本次顺序计算，不推断未收录的前七章。

首页进度显示“可学习章数 / 本次收录章数”，不会把章节数量作为内容正确率。待处理事项包含原资料映射、内容/答案、必要材料和审校缺口，不是遗漏页数；同一来源与目标可能各有一项需要处理。任何范围或记录格式无效时不生成可用结论。

页面接口：`DTHQuality.progress(course)` 返回独立的首页范围区域；`navStatus(course,chapterId)` 返回可供目录使用的纯文本短状态；原 `summary`、`chapter`、`overview` 分别用于章卡片、章首折叠与来源页。不要在整张可点击章卡片内插入范围区的交互控件。

## 保存真实验收记录

可选顶层 `chapterChecks` 保存实际完成的检查。旧教材没有它仍可使用，页面显示未单独验证。每条记录的结构为：

```json
{
  "chapterId":"ch1",
  "kind":"offline",
  "result":"pass",
  "reviewer":"实际执行检查者",
  "method":"浏览器及版本、file://断网、宽窄屏尺寸和实际操作",
  "evidence":"具体结果和局限；不能只写通过",
  "checkedAt":"2026-11-12T10:00:00+08:00",
  "targetIds":["真实检查的小节或题目ID"],
  "checks":["实际执行的检查名"],
  "artifactSHA256":"实际测试HTML文件的64位SHA-256",
  "binding":{"version":1,"fingerprint":"当前章节绑定","rendererFingerprint":"当前构建器和显示资源绑定"}
}
```

`kind` 为 `offline` 或 `visual`；`result` 为 `pass`、`fail` 或 `pending`。targetIds 只列实际检查内容。宽窄屏逐章打开、核对小节与布局，可以记录这些小节的打开/布局检查；并不表示每道题都实际作答。视觉范围只列截图中实际可见并复核的内容。具体操作在 checks、method 和 evidence 中保留。

`chapter-binding` 只计算绑定，不创建检查结论：

```sh
python3 /技能路径/scripts/pipeline.py chapter-binding /工作区/course.json \
  --inventory /工作区/source-inventory.json --chapter ch1 --out /工作区/checks/ch1-binding.json
python3 /技能路径/scripts/pipeline.py chapter-state /工作区/course.json \
  --inventory /工作区/source-inventory.json --out /工作区/checks/chapter-state.json
```

章节内容、相关资料、任务约定、原资料清单或教材版本改变，内容绑定即过期；显示资源或构建器变化，渲染绑定即过期。由于目录与首页范围共享全书状态，其他章节的内容、当前语义审校或独立抽检记录变化也会使既有页面验证过期，不能沿用已经不匹配的导航/状态截图。旧记录保留但不计入当前验证范围。当前绑定下仍有 fail/pending 时，另写 pass 不能覆盖它。修复内容/组件并重新检查后，可追加新绑定记录。

加入记录与验收说明不会改变内容绑定，但会改变 HTML 文件字节。记录保留当时实际测试文件的摘要；嵌入证据后仍须对最终文件复测，最终摘要与报告存工作目录，避免为了匹配摘要无限重建。脚本只核对记录结构、范围与时效，无法技术证明检查者确实做过这些操作。

`chapter-state` 退出 0 仅表示成功生成状态报告，不表示每章验证通过；必须读取各维度状态。不得手工改 `validation.chapterStatus` 把未验证状态涂成通过，构建时会重算。
