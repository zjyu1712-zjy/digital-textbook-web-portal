# 单文件体积与图片副本

构建默认交付一个自包含HTML。资源报告衡量最终文件的实际UTF-8字节，不把大图片藏进“正文”，也不因结构允许未完成就跳过体积上限。报告是工作目录中的验收材料，交给学习者的文件仍可只有HTML。

## 构建报告与阈值

```sh
python3 /技能目录/scripts/pipeline.py build /工作目录/course.json \
  --inventory /工作目录/source-inventory.json --assets /工作目录 \
  --out /工作目录/output/教材.html \
  --size-report /工作目录/checks/size.json --warn-mib 60 --max-mib 100
```

未指定`--size-report`时，CLI在HTML输出路径后追加`.size.json`。MiB按1024×1024字节计算；两个参数必须为正整数，提醒阈值小于阻断阈值。默认**大于60MiB提醒，大于100MiB停止写出本次HTML**。这是可配置的交付预算，不是浏览器性能定律；只有实际目标设备验证和明确交付条件才能支持放宽阈值。已有文件是否仍为旧版应按此次命令退出码和报告判断，不能把失败前留存的旧HTML当成本轮成果。

报告包含：

- `totalBytes`及本次HTML的SHA-256。
- `parts`：图片URI、字体URI、JavaScript、课程数据净额、样式净额、其余HTML。各项互斥，总和等于最终文件字节数；URI前缀与base64均计入资源项，JSON引号等仍计入课程数据。
- 图片原始字节、实际内嵌字节、重复次数、实际解码摘要与来源路径；最大的5项按重复内嵌后的总成本排列。
- 字体原始及内嵌字节、资源数量，以及超限、大图、重复资源等提醒。

同一图片出现三次就按三次计成本，不能用唯一资源大小冒充最终HTML大小。课程数据还包含来源和审查证据，不能把这一项全部视为学习正文。报告不检查图片是否清楚，也不测浏览器内存或首屏耗时。

若超限，先检查最大图片与重复开销。需要优化时使用下面的显式工具；仍过大可按约定章节范围分批制作，每份继续自包含并明示范围。不会自动外置资源、删图、把章节截图替换成摘要，或假定不同HTML之间共享浏览器存储。

## 显式优化图片副本

图片优化使用可选Pillow；无图构建、普通原图内嵌和资源分析不需要它。本轮实际图像测试环境为Pillow13.0.0。优先使用宿主已有环境，不自动改全局依赖。

```sh
python3 /技能目录/scripts/optimize_images.py /原资料/图表.png \
  --out-dir /工作目录/优化图表 --profile diagram
python3 /技能目录/scripts/optimize_images.py /原资料/扫描页.jpg \
  --out-dir /工作目录/优化扫描页 --profile scan --max-edge 2000 --quality 88
```

输出目录必须不存在，其父目录须已经存在。工具不改源图或课程JSON；先检查所有输入，再生成新副本及`optimization-manifest.json`。清单记录原文件与产物的路径、SHA-256、尺寸、格式、帧数、字节和转换动作。产物状态始终是`prepared-needs-review`，不能据此写视觉通过。

| 预设 | 默认行为 | 使用条件 |
| --- | --- | --- |
| `diagram` | 不缩小像素尺寸，使用无损PNG；若无变化且原件更小则保留原字节 | 细字、公式、线条、颜色有含义的图表；可显式设置最长边，但缩小仍可能损失可读性 |
| `scan` | 最长边2000，JPEG质量88，保留颜色 | 扫描原页；灰度必须再明确加`--grayscale`，不能默认丢弃彩色标记 |
| `photo` | 最长边1600，JPEG质量85 | 连续色调照片，仍须检查细节 |

不会放大小图。透明图片使用无损PNG保留透明度；动画按原字节复制，保留全部帧和播放参数，不把首帧冒充原动画。CMYK及高位深等特殊颜色模式也保留原字节，清单明确记录未转换，不静默转成普通RGB。没有几何或灰度转换、重编码却更大时，使用较小原件。最长边和质量是压缩控制，不能保证字节一定减少或教材仍可读。

优化后实际对照源图检查小字、上下标、正负号、虚实线、图例与颜色含义。确认可用后，才把相应`image.path`换成副本、`image.sha256`换成清单的产物摘要，重做受影响的内容审查与视觉检查；原教材的`sources[].sha256`仍代表原资料身份，不能随衍生图片改写。若看不清，放宽尺寸、改用无损原图或重新制作有依据的结构化图表。

## 实现与回归

`scripts/resource_budget.py`提供`analyze_html`和`enforce_budget`，超限异常`ResourceBudgetExceeded`携带真实报告，供CLI和门户保存失败证据。预算执行不依赖内容完整性标记。

`tests/test_resource_budget.py`检查UTF-8分项、重复成本、阈值边界、无效资源和报告可追溯性；`tests/test_optimize_images.py`检查源图不变、像素/透明度/动画保留、显式灰度与缩放、禁止覆盖及失败清理。图像测试须在Pillow环境执行，缺依赖的跳过不能记为通过。图片可读性仍需实际查看，完整教材的设备性能另行实测。

## 1.4.0 本机资源基线

2026-11-12，使用3种自编扫描图样各重复100次，形成300次图像放置；这不是300页真实教材。默认scan处理后，实际内嵌HTML由98,211,710字节降至79,122,509字节（93.662→75.457 MiB，减少19.44%）。300次放置、3种唯一图片和分项总和均由资源分析器实际验证；两份HTML仍高于60 MiB提示阈值。原图摘要保持不变。

逐张对照原图及优化图，小字略软但仍可读，分数线、0.01/0.02、表格细线和颜色图例保留；不据此推断任意教材图片质量。优化耗时0.127秒，原/优化HTML分析耗时0.902/0.741秒，仅为本机此合成负载的单次观测，不代表浏览器载入、手机内存或模型耗时/费用。较高质量输入的第一轮预计超100 MiB，已在写入HTML前中止，没有抬高上限。
