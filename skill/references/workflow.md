# 转换、检查点与增量工作

1. 工作区建立 inputs（只读原件或来源索引）、extraction、chapters、checks、output。已有HTML先复制，计算摘要，不动原Git历史。
2. 文件清单记录SHA、身份、角色、页数、物理页与印刷页映射、可提取文字/扫描状态、缺页/加密/模糊项。脚本 inventory 只扫描指定文件，不进入私人目录。
3. 对主资料逐章建立独立清单；页标题之外还要枚举证明、条件、例题、小问、图表、注释。教师课件主导要逐页映射正文；提纲主导要逐条映射教材展开。
4. 提取文字只是中间证据。表格逐格、矩阵逐行列、例题数据/符号/上下标看原图；统计原始数据不能仅依赖OCR。把原识别值与修正值、页码、原因记入 extraction/corrections.json。不得修改原PDF。
5. 每章保存独立 JSON 与其 sourceItem IDs。先将用户目标、资料用途和各章安排保存为taskContract。模型写完整教学讲解和答案、核对配套解析，并用learningMap逐项记录实际讲解、总结与重点的位置或处理理由。所有模式按 [资料融合的共同要求](material-modes.md#资料融合的共同要求)将纳入学习的资料融入导读、知识点讲解、重点辨析和章末总结，记录各来源承担的作用及重点依据。原资料句子与AI解释的出处区分；不调用在线模型在成品中现答。
6. 实际审查后用review-binding计算当前绑定，连同真实审查结果保存；更新内容或资料后用review-state检查哪些审查已过期，不能重算指纹后直接沿用未复核的pass。详见 [任务约定与审校时效](task-contract-and-review.md)。保存每章内容哈希、源文件/相关页哈希、规则版本、题目/答案版本和已做审查。`checkpoint` 当前工具以已组装chapter与相关questions及共享元数据计算哈希；传 `--previous` 列出受影响章节。来源页级依赖由工作清单维护（不要宣称脚本已有OCR增量调度）。
7. 中断后读清单、检查点与待办，续做未完成章节。改动源文件时确认受影响页与引用题目，重审相关章；规则全局变化可能需要所有章。后续补资料按本任务约定的主次和用途融入，同时检查并更新受影响的导读、讲解、重点总结和练习关联；若新增资料改变了约定主线，再重整相应章节。不能以添加资料入口代替内容融合，也不因补入PPT就改换主资料。核对新主题与旧知识点链接，保留旧原文、来源、稳定章节/题目/字段ID及历史快照；必要的内容纠错按版本规则处理。保留已核准中间内容，不因上下文长度压缩后续章节。
8. 组装统一 course.json；运行结构/公式/资源验证和本次语义审查；将验收说明写入 acceptance 再打包最终副本。最后验证的是实际交付HTML的摘要，不能拿旧构建测试冒充新输出。

失败边界：损坏/缺页/扫描无法确认时记录具体文件、物理页、缺项。范围仍可制作就交付明确未完成的可用副本和待补项；不能填充目录中不存在的正文。不要要求额外辅料作为单本教材转换的先决条件。
