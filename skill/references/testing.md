# 验收与最小修复

## 必做证据

内容：源目录/页范围对照、各类原题独立计数、每题小问/数据/图表/答案来源。定义、条件、推导、解答及材料论证进行语义核查并逐范围登记，不能只写“全通过”。若只检查代表章，其他章标未核查。

功能：各章独立、搜索、知识点往返、所有题型/小问可答、默认隐藏答案、AI标记、同题三次新增、草稿/公式/矩阵/表格/图片恢复、刷新、实际浏览器关闭重开、离线冷启动、完整备份及重复导入、冲突、不同教材隔离、内容升级后旧记录快照、存储拒绝/空间不足、无远程资源。

视觉：实际浏览器宽屏与390px窄屏，公式/矩阵/长表格/折叠/输入，截图人工查看，不只测DOM。长表格可在内部横向滚动，不让全页溢出。记录浏览器版本、file://或HTTP、测试文件SHA。HTTP只能证明HTTP，不替代双击文件。

安全：把含脚本/事件属性/闭合script标签的内容与输入作为测试数据；不执行。备份不安全字段、跨书、缺附件和冲突应拒绝，原数据保留。不要使用真实作答记录做公开测试。

## 可运行测试

- `python3 -m unittest discover -s tests -p 'test_*.py'`：结构反例、公式拒绝、嵌入、安全和增量影响。
- `node tests/browser.cjs <通用样本HTML> <报告路径>`：独立临时profile、file://断网、三次提交、附件、关闭重开、备份、故障注入。
- `node tests/components.cjs <组件样本HTML> <报告路径>`：矩阵/公式/分录/表格/选择、不同教材与内容版本回溯（按实际脚本参数运行）。
- `python3 tests/make_components.py work/components` 生成合成组件三版本；再对其中components.html运行组件测试。
- `node tests/navigation.cjs <组件样本HTML> <报告路径>`：整卷入口、精确位置、连续刷新与跨章往返；异步存储条件必须逐次await，不把Promise当布尔通过。
- 测试不自动证明真实教材完整，须另有 source-inventory 与语义审查。

## 修复闭环

`{issueId,observed,evidence,component/source,minimalFix,round,retest,regression,status}` 保存到工作区。结构、渲染、引用、资源与确定计算可在生成副本修复；缺材料/歧义/冲突只能标记或补材料。默认同类问题三轮仍失败就停该修复链，输出具体阻塞与可用部分；用户明确要求继续时遵从后续指令，持续定位与复测，不以次数代替解决问题。

禁止删除难题、题设/测试断言、关闭保存、隐藏公式或换成联网资源来通过测试。升级旧HTML先备份，再核对ID、数据库和导入格式，迁移测试必须有旧样本和恢复路径。报告分 pass/fail/unverified，不把静态代码检查称为浏览器通过。自检只在本次调用执行，不承诺后台监控。
