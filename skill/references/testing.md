# 验收与最小修复

## 必做证据

内容：源目录/页范围对照、各类原题独立计数、每题小问/数据/图表/答案来源。定义、条件、推导、解答及材料论证进行语义核查并逐范围登记，不能只写“全通过”。若只检查代表章，其他章标未核查。

资料融合另查：所有模式逐主题对读各资料中要求纳入学习的实质条目与成品实际讲解，记录来源定位、讲解位置和修复结果；检查导读、总结和重点是否体现用户约定的资料作用，不能只查页数、链接和映射数量。资料明确只用于存档或对照时按其用途验收。已约定后续补资料的章节如实显示待补并保留现有内容；补入后复核受影响的讲解、总结、重点、练习关联与旧入口。课件主导才核查是否采用课堂主线；其他模式按各自约定主线验收，不以原页显示成功判定融合通过。

功能：各章独立、搜索、知识点往返、所有题型/小问可答、默认隐藏答案、AI标记、同题三次新增、草稿/公式/矩阵/表格/图片恢复、刷新、实际浏览器关闭重开、离线冷启动、完整备份及重复导入、冲突、不同教材隔离、内容升级后旧记录快照、存储拒绝/空间不足、无远程资源。

错题本另查客观错误与显式标记、手动撤销、正确重做保留记录、新错答恢复待复习、分章筛选、附件导出与完整备份恢复、版本不混并、ID迁移/删题以及只读禁写。旧模糊判分不因出现“不正确”三个字就自动收录。

视觉：实际浏览器宽屏与390px窄屏，公式/矩阵/长表格/折叠/输入，截图人工查看，不只测DOM。长表格可在内部横向滚动，不让全页溢出。记录浏览器版本、file://或HTTP、测试文件SHA。HTTP只能证明HTTP，不替代双击文件。

章首检查主要学习路径与复习、原资料入口是否层次清楚；目录较长时查看完整目录，不能仅凭首屏截图判定布局。若补充资料使用折叠，须从搜索、题目知识点和旧链接实际跳转，验证目标可见且往返草稿仍保留。

安全：把含脚本/事件属性/闭合script标签的内容与输入作为测试数据；不执行。备份不安全字段、跨书、缺附件和冲突应拒绝，原数据保留。不要使用真实作答记录做公开测试。

## 任务约定与审校时效的反例

新v2数据必须覆盖：混合资料未定主次不猜PPT优先；已有organization及章计划被尊重；用途引用非法源/章、重叠用途或主资料冲突被拒绝；只附原页不能标为integrated；仅对照的资料不能被当作主线。正文、相关来源、任务用途或融合处理改动后，旧pass必须失效；重新实际审查并绑定后才恢复通过。保持记录与目标ID不变也不能绕过时效检查。

review-binding只计算指纹，不能创建pass；review-state不能替代完整validate或实际语义对读。v1兼容构建应显示legacy-unverified，不自动转换为新审校通过。v1→v2用隔离浏览器验证旧草稿与提交快照，不能使用真实学生记录作为公开样本。

独立抽检必须先持久化原文观察，再提供生成内容；已有语义pass、生成者自述和修复结论不进入原文先读请求。参考用途不强求融合；未映射条目不得从样本候选中消失。计划、原文观察、题设或统一试卷条件变化时，检查旧结论失效。样本通过与全文完成分开显示。章级状态须验证缺证据、部分范围、旧渲染器、无效融合和仅参考原页的分支，不能根据下载成功或全局构建结果补画通过。

## 可运行测试

转换成品优先使用 `node /技能绝对路径/tests/runtime-check.cjs /工作区/教材.html /工作区/checks/runtime-report.json`，它读取本次教材真实 ID 与题型；`pass` 退出 0，`fail` 退出 1，缺能力等 `unverified` 退出 2。报告中的 `not_applicable` 不计为通过。真实截图仍需查看。Playwright 可放在工作区的 node_modules 或技能根目录，或使用 PLAYWRIGHT_MODULE 的绝对路径；浏览器用 BROWSER_EXECUTABLE 指定。

以下固定样本脚本用于开发回归；从安装目录外调用时给脚本、输入和输出传绝对路径，并用 PLAYWRIGHT_MODULE 指定现有模块。工作文件不要放进只读安装目录。

- `python3 -m unittest discover -s tests -p 'test_*.py'`：结构反例、公式拒绝、嵌入、安全、增量影响、跨目录/编码、环境失败和发布包隐私边界。
- `node tests/browser.cjs <通用样本HTML> <报告路径>`：独立临时profile、file://断网、三次提交、附件、关闭重开、备份、故障注入。
- `node tests/components.cjs <组件样本HTML> <报告路径>`：矩阵/公式/分录/表格/选择、不同教材与内容版本回溯（按实际脚本参数运行）。
- `python3 tests/make_components.py work/components` 生成合成组件三版本；再对其中components.html运行组件测试。
- `node tests/navigation.cjs <组件样本HTML> <报告路径>`：整卷入口、精确位置、连续刷新与跨章往返；异步存储条件必须逐次await，不把Promise当布尔通过。
- `node tests/assurance.cjs <旧v1HTML> <当前v2HTML> <过期审校HTML> <新构建v1HTML> <报告路径>`：合成样本验证v1→v2记录恢复、任务用途与融合位置展示、当前/过期/旧版状态及离线运行；截图另行人工核查。
- `node tests/grading.cjs`：规则缺项、精度丢失、数值格式和十进制容差边界；`tests/grading-ui.cjs`验证真实页面中格式错误不产生误判提交，具体参数见脚本。
- `node tests/demo.cjs <示例HTML> <输出目录>`：自编示例的实际作答、公式预览、20个字体离线加载、备份下载及宽窄屏截图。
- `node tests/mistakes.cjs` 与 `node tests/mistakes-ui.cjs <自写示例HTML> <输出目录>`：错题规则与真实离线复习、导出、迁移、只读故障；详见[错题本](mistakes.md)。
- `node tests/quality-ui.cjs <示例HTML> <输出目录>`：首页紧凑状态、章首默认折叠、展开范围、来源表及真实导航；宽窄屏完整截图需另行实际查看，脚本不替代视觉结论。
- 测试不自动证明真实教材完整，须另有 source-inventory 与语义审查。

存储故障回归必须保留已有历史及图片：分别注入启动写失败、启动读回失败和运行中配额失败，核对只读时仍能导出完整已保存记录、未保存草稿另行导出，不能提交/导入或误报成功，刷新恢复后重新探测。不能只测“报错文字出现”。环境检测另查工作区失败不连带误报Node/公式失败；字体打包逐文件核对字节和字体族/字重/样式，并实际在断网浏览器加载。

## 修复闭环

`{issueId,observed,evidence,component/source,minimalFix,round,retest,regression,status}` 保存到工作区。结构、渲染、引用、资源与确定计算可在生成副本修复；缺材料/歧义/冲突只能标记或补材料。默认同类问题三轮仍失败就停该修复链，输出具体阻塞与可用部分；用户明确要求继续时遵从后续指令，持续定位与复测，不以次数代替解决问题。

禁止删除难题、题设/测试断言、关闭保存、隐藏公式或换成联网资源来通过测试。升级旧HTML先备份，再核对ID、数据库和导入格式，迁移测试必须有旧样本和恢复路径。报告分 pass/fail/unverified，不把静态代码检查称为浏览器通过。自检只在本次调用执行，不承诺后台监控。
