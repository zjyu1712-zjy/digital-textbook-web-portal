# 1.0.1 草稿保存修复

问题：成功保存后，内存中的导航缓存仍保存旧的草稿版本号。同一页面从题目跳到知识点再回来时，会把自己的新记录误判为其他页面修改，产生不必要的分叉草稿。

最小修复：保存成功后，将含最新版本号的草稿同步到 `memoryDrafts`。真正多页面编辑时的冲突检测与分叉保护保留；不删除旧记录，不修改数据库结构，不改变题目或答案。

在自编通用测试节选上先复现：无其他页面并发编辑，仍产生 3 条带 `forkOf` 的草稿，预期应为 0。修复后为 0。回归断言位于 `tests/runtime-check.cjs` 的 `single-page-no-false-conflicts` 检查。

同一修复最先在网页工程专用 Skill 副本中验证，此发布版把它纳入独立 Skill。仅同步通用组件修复与可独立执行的回归脚本；不带网页服务、任务数据或模型凭据。

开发验证：Microsoft Edge 155.0.4283.62，真实 `file://`、断网与隔离浏览器数据目录。

- 自编通用节选：17 项通过，1 项不适用。
- 九题型合成组件：17 项通过，1 项不适用。
- 无题教材分支：11 项通过，7 项不适用。

覆盖浏览器关闭重开、草稿/附件、三次提交、备份及相关持久化回归。样本范围有限，不等同于五门课程全量重跑或所有浏览器、任意教材均已验证。自动测试不能替代来源与语义审查；学科内容和实际截图仍按 Skill 流程核查。
